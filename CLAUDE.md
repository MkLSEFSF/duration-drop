# Working preferences

## When starting a new project
- Before the first shell command in a repo, check its recorded facts with `zizi-skills:project-config` (install, run, build, test, lint commands).
- For any non-trivial feature or multi-file change, use `superpowers:brainstorming` to clarify intent, then `superpowers:writing-plans` (or `zizi-skills:planning`) and get approval before building.
- Write tests first for new behavior with `superpowers:test-driven-development` or `zizi-skills:tdd-skill`.
- Use `superpowers:systematic-debugging` for any bug or unexpected failure before proposing a fix.
- Before claiming work is done or passing, run `superpowers:verification-before-completion`.
- Use `superpowers:using-git-worktrees` for feature work that needs isolation.
- Use `zizi-skills:git-sync` before commits, pushes and PRs.
- Use `find-skills` only when I explicitly ask for a skill.
